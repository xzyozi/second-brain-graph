# ADR 0003: 書き込み境界ガード (edit_guard) と新規ファイル許可 (allowed_new_file_globs)

- **日付**: 2026-11-04
- **ステータス**: Accepted
- **関連Issue**: Epic #116, #101, #102, #125

## コンテキスト (Context)
コード編集エンジン（Aider / agy）は、自律的に作業ツリーのファイルを走査・編集・新規作成する能力を持つ。
このとき、以下のリスクが存在する：
1. 母艦リポジトリ（`second-brain-graph`）自身を作業ツリーと誤認して改変・破壊するリスク。
2. 作業ツリー内の秘密情報ファイル（`.env`, `*.pem` 等）を誤って編集・送信・ステージするリスク。
3. `target_files` 外の無関係なファイルを勝手に作成または改変するリスク。
4. 一方で、多言語（Rust, TypeScript 等）のサテライトにおいて、新機能の実装に伴い新しいヘルパーやテストファイルを自律作成する必要がある。

## 決定事項 (Decision)
1. **境界防護の集約 (`tools/edit_guard.py`)**:
   - エンジン非依存の境界ガードモジュール `tools/edit_guard.py` を新設し、実行前検証と事後ロールバックを集約する。
   - 母艦リポジトリ自身の直接指定、および母艦内部ディレクトリ（`tools/`, `config/` 等）の指定を例外（`MotherRepositoryProtectionError`）として即時拒絶する。
   - 実行前に秘密情報ファイルを検知し、警告を出力する。
   - 編集完了後、`target_files` 外の変更を検知し、未追跡ファイルは削除、追跡済みファイルの勝手な変更は HEAD に復元する。

2. **サテライト新規ファイル許可基盤 (`allowed_new_file_globs`)**:
   - サテライトごとの `project.json` に任意項目 `allowed_new_file_globs`（例: `["tests/**", "src/**/*.rs"]`）を設定可能とする。
   - 未追跡ファイルが該当 glob に一致する場合、サニタイザによる削除を免除して保持し、オーケストレーターの `target_files` に動的追加・登録する。
   - 追跡済みファイルに関しては、たとえ glob に一致していても `target_files` 外の変更であれば必ず HEAD に復元する（既存設定ファイル等の改変防止）。
   - `doctor` において `allowed_new_file_globs` の形式チェック（文字列リスト）を実施する。

## 結果・影響 (Consequences)
- 母艦の保護と既存設定の改変防止という厳格な安全性を維持しながら、サテライトにおける多言語での自律的な新規テスト・モジュール作成が実現された。
