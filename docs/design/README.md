# 設計ドキュメント作成・運用ガイドライン

本ガイドラインは、プロジェクトにおける設計仕様書（基本設計、詳細設計、データ構造仕様）の作成、命名、参照、および運用の標準ルールを定めたものです。
他プロジェクトや別環境へ展開・移植する場合でも一貫したドキュメント品質を保持できるよう、以下の規則を順守してください。

---

## 1. ドキュメントの分類とテンプレート選択

作成する設計書の目的に応じて、以下のテンプレートの中から最適なものを選択して作成してください。

| 分類 | テンプレートファイル | 主な記述内容・適用目的 |
| :--- | :--- | :--- |
| **基本設計書** | `TEMPLATE_基本設計書.md` | システム全体の目的、アーキテクチャ方針、コンポーネント分離、システム境界、依存関係の定義 |
| **詳細設計書** | `TEMPLATE_詳細設計書.md` | 特定モジュール・関数の入出力パラメータ、状態遷移ルーティング、エラーハンドリング、単体テスト要件 |
| **データ構造仕様書** | `TEMPLATE_データ構造仕様書.md` | JSON/Pydantic等のスキーマ、状態タクソノミー、配置ディレクトリ、原子置換契約、排他制御仕様 |

---

## 2. 命名ルール方針 (Naming Conventions)

ドキュメントのファイル名および識別表記は、以下の統一命名ルールに従って定義してください。

### 標準命名フォーマット
`[PROJECT_PREFIX]-[TYPE_CODE]-[NUMBER]_[DOCUMENT_TITLE].md`

### 各要素の定義
1. **`PROJECT_PREFIX` (プロジェクト識別子)**:
   - 各リポジトリ・プロジェクトごとに定義する識別コード（英大文字 2〜5 桁）。
   - 例: `SBOS` (Second Brain OS), `APP` (アプリケーション基盤), `CORE` (コアエンジン)
2. **`TYPE_CODE` (種別コード)**:
   - **`BD`**: 基本設計書 (Basic Design)
   - **`DD`**: 詳細設計書 (Detailed Design)
   - **`DS`**: データ構造仕様書 (Data Structure Specification)
   - **`ENV`**: 環境構築仕様書 (Environment)
   - **`OP`**: 運用詳細設計書 (Operation)
   - **`PM`**: 課題矛盾一覧 (Problem Management)
3. **`NUMBER` (連番)**:
   - 3桁のゼロパディング連番（例: `001`, `002`, `003`）
4. **`DOCUMENT_TITLE` (ドキュメント名)**:
   - 内容を表す日本語タイトル（例: `基本設計書`, `Backend_GPUリース仕様`）

#### 命名例
- `SBOS-BD-002_基本設計書.md`
- `PROJECT_KEY-DD-005_Backend_GPUリース仕様.md`

## 3. 参照およびハイパーリンクの運用ルール

### ① 特定環境依存ハイパーリンク（`file:///...` 等）の禁止
- 特定マシンの絶対パス（`file:///C:/Users/...` や環境固有の完全絶対URL）をドキュメント内に直接埋め込むことを**禁止**します。
- **背景・理由**: リポジトリを別の開発環境やCI/CD環境、別プロジェクトへ移植・共有した際に、リンク切れや参照不可が発生するためです。

### ② ドキュメント参照および相対リンクの推奨
- 他ドキュメントを参照する場合は、**標準的な文書名テキスト**（例: `SBOS-BD-002（基本設計書）`）で記述します。
- 同一リポジトリ内での移動を補助する場合は、環境に依存しない**リポジトリ相対パスリンク**（例: `[Backend仕様](./SBOS-DD-005_Backend_GPUリース仕様.md)`）を使用してください。

### ③ 具象ソースコードの非掲載
- プログラムコード（Python、Shell、Bash 等）の具象コードブロックをドキュメント内に貼らないでください。
- パラメータ表、入出力型、バリデーション制約、事前・事後条件、エラー判定ルール等のテキスト・テーブル構造で仕様を記述してください。

### ④ 単一責任原則 (Single Source of Truth: SSOT)
- 特定コンポーネントの詳細仕様は、対応する詳細設計書またはデータ構造仕様書を正本として一元管理してください。
- 複数のドキュメントに同一の仕様を重複掲載せず、正本となる設計書への参照に留めてください。
