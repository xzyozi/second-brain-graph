# [TFG-0008] ignore_case 検索におけるループ内の不要な処理の最適化

## 0. メタ情報 (Scope & Impact)
- **影響範囲**: `projects/test_file_grep` 内の検索性能改善
- **既存コードへの依存**: あり（`src/grep/engine.py` の `_check_hit` およびループ処理）
- **関連Issue**: GitHub Issue #4

## 1. 概要・背景
`GrepEngine._check_hit()` メソッド内において、大文字・小文字を区別しない検索 (`ignore_case=True`) を行う際、ファイルの各行に対して `search_text.lower() in line.lower()` が評価されています。検索対象の文字列 (`search_text`) の小文字化は行ごとに変動しないため、ループ内で毎回計算するのは非効率です。
これをループの外側で事前に一度だけ小文字化（プリコンパイル/事前変換）しておくことで、行走査ループの不要なオーバーヘッドを削減します。

## 2. 仕様および要求事項
- [ ] `ignore_case=True` かつ `regex_mode=False` の場合、検索文字列 `search_text.lower()` の計算を各行の走査ループ前（呼び出し元、またはキャッシュ）に一度だけ行うようリファクタリングする。
- [ ] 既存の検索結果（マッチ行、行番号、大文字小文字無視の一致判定）の正確性を損なわないこと。
- [ ] 大文字・小文字を区別しない検索に関するテストケースを `tests/test_engine.py` に追加・補強する。

## 3. 段階的実装手順 (Step-by-step Execution)
- **Phase 1 (Core Implementation)**: `src/grep/engine.py` 内のテキスト走査ループおよび `_check_hit` のシグネチャ/呼び出し方法を見直し、事前処理された検索文字列を利用するように修正。
- **Phase 2 (Test Implementation & Refinement)**: `tests/test_engine.py` において、`ignore_case=True` の検索が正常に動作することを確認し、既存テストがすべて通過することを確認する。

## 4. 編集対象ファイル (Target Files)
- `src/grep/engine.py`
- `tests/test_engine.py`

## 5. 設計制約・アンチパターンの禁止 (Architecture Constraints & Forbidden Actions)
- **既存インターフェースの互換性維持**: `search_file` などの公開 API の引数・戻り値型を変更しないこと。
- **堅牢な処理**: `search_text` が空文字やマルチバイト文字の場合でも例外を発生させないこと。

## 6. 完了定義 (Definition of Done)
- [ ] 行走査ループ内で `search_text.lower()` が毎行再計算されない構造になっていること。
- [ ] 単体テスト（`pytest tests/test_engine.py`）がすべてパスすること。
- [ ] Ruff の静的解析エラーがないこと。
