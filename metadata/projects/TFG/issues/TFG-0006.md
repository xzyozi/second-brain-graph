# [TFG-0006] 暗号化・パスワード保護Officeドキュメントの自動判定・復号パース機構と構造例外処理の設計・実装

## 1. 概要・背景
現在の `office_parser.py` / `engine.py` は、暗号化またはパスワード保護された Office ドキュメント（docx, xlsx, pptx）が入力された場合、内部の `zipfile.ZipFile` が `BadZipFile` や `RuntimeError` などの汎用的な例外を送出して壊滅的に停止します。
本タスクでは、既存のパース仕様では対処できない「暗号化ヘッダーの自動判別」「復号化用パスワード試行コールバック/コンテキスト構造の分離」「専用例外 `EncryptedFileError` への集約と検索スコープ保護」を設計・実装し、高度な障害耐性を獲得します。

## 2. 仕様および要求事項
- [ ] **暗号化シグネチャ判定**: ファイルのバイナリヘッダー（OLE2 Compound File Header や EncryptionInfo ストリーム等）をチェックし、標準 Zip 圧縮でないパスワード保護ドキュメントをパース前に即座に判別する判定関数 `is_encrypted_office_file(file_path: str) -> bool` を実装すること。
- [ ] **復号およびパース抽象化**: パスワードが与えられた場合（またはデフォルトパスワードリスト試行時）に、メモリ上（`io.BytesIO`）で非破綻でストリーム復号してパースを行うプロキシレイヤーを実装すること。
- [ ] **例外カスケードの統合**: パスワード不一致や復号不能な暗号化ファイルが検出された場合、無関係な内部スタックトレースを露出させず、明確な `EncryptedFileError` 例外を送出してエンジン側で `SKIPPED_ENCRYPTED` として安全にハンドリングできる構造にすること。
- [ ] **非同期/ストリーム対応**: 復号時にディスクへ平文ファイルを一次保存して漏洩するリスクを防ぐため、完全メモリインメモリ処理を強制すること。

## 3. 編集対象ファイル (Target Files)
- `src/grep/office_parser.py`
- `src/grep/engine.py`
- `src/grep/interface.py`
- `tests/test_office_parser.py`
- `tests/test_engine.py`

## 4. 除外条件・禁止事項 (Forbidden Actions)
- ディスク上に復号後の未暗号化テンポラリファイルを一切生成・残存させないこと（セキュリティ保護規約）。
- 既存の非暗号化ファイルに対するパース性能（スループット）を劣化させないこと。
- `settings.json` などのグローバル設定ファイルを無断で変更しないこと。

## 5. 完了定義 (Definition of Done)
- [ ] パスワード保護されたテストサンプルファイルに対し、`is_encrypted_office_file` が正しく `True` を返すこと。
- [ ] パスワード未指定時に `EncryptedFileError` が捕捉され、検索エンジンがクラッシュせず適切にスキップログを記録すること。
- [ ] 正しいパスワードコンテキストを渡した際に、インメモリ復号されてテキスト検索が正常完了すること。
- [ ] `pytest` 単体テストがすべて通過し、`ruff check` エラーが 0 件であること。
