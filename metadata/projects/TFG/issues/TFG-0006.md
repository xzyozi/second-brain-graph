# [TFG-0006] 暗号化・パスワード保護Officeドキュメントの自動判定・復号パース機構と構造例外処理の設計・実装

## 1. 概要・背景
grep検索エンジンにおいて、XLSXおよびDOCXファイルをパースし、テキストを検索対象に含める。暗号化またはパスワード保護されたファイルの場合は、暗号化ヘッダーを判別して復号処理を試行してからパースする。

## 2. 仕様および要求事項
- [ ] **暗号化シグネチャ判定**: ファイルのバイナリヘッダーをチェックし、標準 Zip 圧縮でないパスワード保護ドキュメントをパース前に判別する関数 `is_encrypted_office_file(file_path: str) -> bool` を実装すること。
- [ ] **復号およびパース処理**: パスワードが与えられた場合にメモリ上で復号してパースを行う処理を実装すること。
- [ ] **専用例外への集約**: パスワード不一致や復号不能なファイルが検出された場合、`EncryptedFileError` 例外を送出してエンジン側で安全にスキップ処理できる構造とすること。

## 3. 段階的実装手順 (Step-by-step Execution)
- **Phase 1 (Core Implementation)**: まず `src/` 配下の本体モジュール・主要ロジック・例外クラスのみを最小変更で優先実装すること。
- **Phase 2 (Test Implementation & Refinement)**: 本体実装完了後、`tests/` 配下の単体テストを作成・修正し、テスト通過を確認すること。

## 4. 編集対象ファイル (Target Files)
- `src/grep/office_parser.py`
- `src/grep/engine.py`
- `src/grep/interface.py`
- `tests/test_office_parser.py`
- `tests/test_engine.py`

## 5. 設計制約・アンチパターンの禁止 (Architecture Constraints & Forbidden Actions)
安定した品質を維持するため、以下のアーキテクチャ原則を厳守すること：
- **単一責任と一方向のデータフロー**: 関数やクラス間で「相互呼び出し（循環依存・無限再帰）」となる設計を絶対に行わないこと。各機能は単一責任（SRP）を持たせ、処理結果は戻り値（またはストリーム等）として上位の呼び出し元に返し、制御フローを上位に委譲すること。
- **ハック的なフロー制御の禁止**: ループや再帰の停止条件として、不自然なフラグ変数（`is_first_time` 等）や深さカウンターなどの場当たり的な実装（ハック）を用いないこと。
- **堅牢な解析ロジック**: 外部データやファイル構造のパース処理において、特定の名前空間やマジックストリングのみを前提とした脆弱なハードコーディングを行わないこと。標準APIの安全な走査（ワイルドカードやイテレータ等）を利用すること。
- **既存の破壊禁止**: 無関係な設定ファイルやインターフェースを変更しないこと。既存の公開 API シグネチャを破壊しないこと。

## 6. 完了定義 (Definition of Done)
- [ ] パスワード保護されたテストファイルに対し、`is_encrypted_office_file` が正しく `True` を返すこと。
- [ ] パスワード未指定時に `EncryptedFileError` が捕捉され、検索エンジンがクラッシュせず適切にスキップログを記録すること。
- [ ] 正しいパスワードを渡した際に、インメモリ復号されてテキスト検索が正常完了すること。
- [ ] `pytest` 単体テストがすべて通過し、`ruff check` エラーが 0 件であること。
